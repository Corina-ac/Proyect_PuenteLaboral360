Datos y Estructuras de Intercambio

Simulación de cómo se organizarían las certificaciones en JSON y XML.

Ejemplo JSON

Esta estructura describe las certificaciones que se muestran en mi portafolio.

{
  "id": 1,
  "nombre": "Certificación Base de Datos SQL",
  "descripcion": "Curso intensivo en diseño de esquemas, consultas JOIN y normalización.",
  "estado": "Completado",
  "fecha": "2026-05-18",
  "instructor": "María López",
  "categoria": "Data"
}

Ejemplo XML

La misma certificación representada en XML para un intercambio de datos alternativo.

<certificacion>
  <id>1</id>
  <nombre>Certificación Base de Datos SQL</nombre>
  <descripcion>Curso intensivo en diseño de esquemas, consultas JOIN y normalización.</descripcion>
  <estado>Completado</estado>
  <fecha>2026-05-18</fecha>
  <instructor>María López</instructor>
  <categoria>Data</categoria>
</certificacion>

Relación entre la interfaz y los datos

Elemento de la interfaz

  • Nombre de la certificación
  • Descripción
  • Estado
  • Fecha
  • Instructor
  • Categoría

Campo JSON / XML

  • nombre / <nombre>
  • descripcion / <descripcion>
  • estado / <estado>
  • fecha / <fecha>
  • instructor / <instructor>
  • categoria / <categoria>

Estos ejemplos corresponden al primer parcial, cuando los datos aún se escribían a mano en data/datos.json y data/datos.xml. En la versión actual la información se carga realmente con fetch() desde la carpeta json/ (9 archivos relacionados por identificador) y se conserva en localStorage entre sesiones.
